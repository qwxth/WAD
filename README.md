[H1] Лабораторная работа номер 3 - Создание REST веб-сервиса для SPA

[LINE]

[H2] Цель работы

Создание REST веб-сервиса в бэкенде системы для использования его в одностраничном приложении (SPA). Веб-сервис реализует всю бизнес-логику домена паттернов нагрузки без браузерного интерфейса, подключается к PostgreSQL через ORM, хранит загружаемые изображения и видео в MinIO.

[LINE]

[H2] Общие требования

- Все URL веб-сервиса начинаются с префикса /api/load_patterns для домена паттернов и /api/users для домена пользователей.
- Все операции с базой данных выполняются через ORM SQLAlchemy.
- Удалённые записи (статус deleted) никогда не передаются клиенту ни в списке, ни по прямому запросу через ID.
- Статусы паттерна образуют одностороннюю цепочку: draft переходит в published при публикации, любой статус может перейти в deleted при удалении. Обратный переход запрещён.
- Системные поля - идентификатор записи, статус, идентификатор создателя, даты создания и публикации - не принимаются от клиента ни в одном методе, вычисляются сервером самостоятельно.
- Изображение и видео передаются как файлы через multipart/form-data, а не как текстовые ссылки. Загруженные файлы получают латинские имена при сохранении в MinIO.
- Текущий авторизованный пользователь определяется через сессию (см. раздел "Механизм авторизации" ниже).

[LINE]

[H2] Методы домена load_patterns

Всего реализовано 8 методов.

[CODE]
[ROW] Номер [COL] Метод [COL] URL [COL] Тело запроса [COL] Тело ответа [COL] Назначение
[ROW] 1 [COL] GET [COL] /api/load_patterns [COL] Query-параметры: max_expected, min_rps, max_rps, search, is_owner [COL] Список объектов паттернов и общее число найденных записей [COL] Получить список опубликованных паттернов с фильтрацией
[ROW] 2 [COL] POST [COL] /api/load_patterns [COL] multipart/form-data: pattern_name (обязательно), description, use_case, image, video (необязательно) [COL] Созданный черновик паттерна [COL] Создать новый черновик паттерна нагрузки
[ROW] 3 [COL] GET [COL] /api/load_patterns/feed [COL] Query-параметры: current_id, another (0 или 1) [COL] Один объект паттерна (не список) [COL] Получить ленту - одну случайную или следующую опубликованную запись
[ROW] 4 [COL] GET [COL] /api/load_patterns/draft [COL] Без параметров, без идентификатора в URL [COL] Черновик текущего авторизованного пользователя [COL] Получить незавершённый черновик текущего пользователя
[ROW] 5 [COL] GET [COL] /api/load_patterns/{pattern_id} [COL] Query-параметр next (true или false) [COL] Объект паттерна - запрошенный или следующий по идентификатору [COL] Получить конкретный паттерн, либо следующий по кругу при next равном true
[ROW] 6 [COL] PUT [COL] /api/load_patterns/{pattern_id}/publish [COL] JSON: requests_per_second, peak_multiplier, duration_hours, description и другие поля публикации [COL] Опубликованный объект паттерна [COL] Опубликовать черновик, перевести статус draft в published
[ROW] 7 [COL] DELETE [COL] /api/load_patterns/{pattern_id} [COL] Без тела запроса [COL] Сообщение об успешном удалении [COL] Логически удалить собственный паттерн, перевести статус в deleted
[ROW] 8 [COL] POST [COL] /api/load_patterns/{pattern_id}/like [COL] JSON: value (0 или 1) [COL] Сообщение об изменении статуса лайка [COL] Поставить или снять лайк с паттерна
[/CODE]

Методы 1, 3, 4, 5 доступны без авторизации (гостю). Методы 2, 6, 7, 8 требуют авторизации через сессию и доступны только автору записи (для удаления и публикации).

[H2] Механизм определения текущего пользователя

В исходной версии данной лабораторной работы текущий пользователь определялся функцией-одиночкой (singleton), возвращающей постоянное значение идентификатора без реальной проверки личности. В лабораторной работе номер 4 этот механизм полностью заменён на авторизацию через сессии, хранящиеся в Redis, и передаваемые клиенту через httponly cookie. Подробное описание нового механизма находится в разделе про лабораторную работу номер 4 этого документа.

[H2] Порядок показа при защите

Скрины с первого по десятый - демонстрация в Postman всех 8 методов домена load_patterns и методов регистрации и аутентификации домена users, строго по порядку, заданному в техническом задании.

Скрины с одиннадцатого по тринадцатый - выборки SELECT в Adminer, подтверждающие изменения в таблицах load_patterns, pattern_likes и users после вызовов через Postman.

Скрины четырнадцать и пятнадцать - исходный код ORM-моделей и Pydantic-сериализаторов.

Скрины шестнадцать и семнадцать - исходный код функции определения текущего пользователя и раздел README с описанием методов и таблиц.

[LINE]

[H2] Технологический стек

Backend - FastAPI на Python версии 3.10 и выше. ORM - SQLAlchemy с миграциями Alembic. База данных - PostgreSQL. Хранилище файлов - MinIO, S3-совместимое хранилище. Формат передачи файлов - multipart form data.

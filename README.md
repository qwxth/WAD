# Лабораторная работа №4 — Авторизация и Swagger

## Цель работы

Завершение бэкенда для SPA: реализация полноценной аутентификации и авторизации вместо временной функции-одиночки, автоматическое определение автора записи из сессии, подготовка документации Swagger с разделением прав доступа для гостя и авторизованного пользователя.

## Механизм авторизации

Авторизация построена на серверных сессиях с хранением в Redis и передачей идентификатора сессии через cookie.

Порядок работы:

1. Клиент отправляет `POST /api/users/login` с логином и паролем.
2. Сервер проверяет хеш пароля, генерирует случайный `session_id` (64 символа, `secrets.token_hex`), сохраняет пару `session_id → user_id` в Redis с временем жизни 24 часа (`SETEX`).
3. Сервер возвращает клиенту cookie `session_id` с флагами `httponly` (недоступна для чтения из JavaScript) и `samesite=lax`.
4. При каждом следующем запросе к защищённым методам сервер читает cookie, находит `user_id` в Redis, подгружает пользователя из базы данных через `Depends`.
5. При `POST /api/users/logout` запись удаляется из Redis (`DEL`), cookie удаляется из браузера.

Для публичных методов (просмотр списка, ленты, конкретного паттерна, черновика текущего пользователя) используется мягкая зависимость `get_current_user_optional`, которая не выбрасывает ошибку при отсутствии сессии, а возвращает `None` — в этом случае `is_owner` и `is_liked` в ответе равны 0.

Для методов создателя (создание черновика, публикация, удаление, лайк) используется строгая зависимость `get_current_user`, которая возвращает код `401 Unauthorized`, если сессия отсутствует или истекла.

Поле `creator_id` в таблице `load_patterns` при создании записи заполняется автоматически из текущей сессии — значение не принимается от клиента ни в каком виде.

## Методы домена `users`

| Метод | URL | Авторизация | Описание |
|-------|-----|--------------|----------|
| POST | `/api/users/register` | Не требуется | Регистрация пользователя, пароль хранится в виде SHA-256 хеша |
| POST | `/api/users/login` | Не требуется | Проверка пароля, создание сессии в Redis, установка cookie `session_id` |
| POST | `/api/users/logout` | Требуется | Удаление сессии из Redis, удаление cookie |

## Доступ без авторизации и с авторизацией

**Без авторизации (гость):**
- `GET /api/load_patterns` — список опубликованных паттернов
- `GET /api/load_patterns/feed` — лента
- `GET /api/load_patterns/{id}` — конкретный паттерн, в том числе переход `next=true`

**Требуют авторизацию (создатель):**
- `GET /api/load_patterns/draft` — черновик текущего пользователя
- `POST /api/load_patterns` — создание черновика
- `PUT /api/load_patterns/{id}/publish` — публикация (только автор)
- `DELETE /api/load_patterns/{id}` — удаление (только автор)
- `POST /api/load_patterns/{id}/like` — лайк

Попытка вызвать метод создателя без действующей сессии возвращает `401 Unauthorized` с сообщением `"Требуется аутентификация"`.

## Описание в Swagger

Документация Swagger (`/docs`) настроена через `tags_metadata` в `main.py` с отдельными описаниями для тэгов `load_patterns` и `users`. Схема авторизации — `APIKeyCookie` с именем `session_id`, в интерфейсе `/docs` отображается кнопкой **Authorize** в правом верхнем углу.

Поскольку Swagger UI выполняет запросы из браузера на тот же origin, что и сам сервер, после выполнения `POST /api/users/login` через `Try it out` браузер автоматически сохраняет полученную cookie, и последующие вызовы защищённых методов в том же окне `/docs` проходят успешно без дополнительных действий.

Маршруты серверного рендеринга (SSR-страницы из лабораторной работы №2) исключены из схемы Swagger через параметр `include_in_schema=False`, чтобы документация содержала только методы REST API.

## Порядок показа при защите

- **Скрины 1–3** — аутентификация через Swagger в окне инкогнито: запрос списка услуг без авторизации, вход через `POST /api/users/login`, повторный запрос защищённого метода в том же окне Swagger с уже установленной cookie.
- **Скрины 4–5** — `GET` всех услуг в Insomnia/Postman, демонстрация, что метод работает независимо от наличия токена/cookie.
- **Скрины 6–8** — `PUT` публикации: запрос от имени гостя (401/403), запрос от имени авторизованного пользователя с успешным обновлением полей, содержимое Redis через консоль (`redis-cli KEYS "session:*"`), подтверждающее наличие сессии.
- **Скрин 9** — Sequence-диаграмма в StarUML со свойством `signature` у сообщений, переиспользованным из диаграммы классов.

## Технологический стек

- Redis 7 (Alpine) — хранилище сессий
- Cookie: `httponly`, `samesite=lax`, время жизни 24 часа
- Хеширование пароля: SHA-256
- FastAPI `APIKeyCookie` для интеграции схемы авторизации со Swagger UI

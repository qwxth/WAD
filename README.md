# Лабораторная работа №3 — Создание REST веб-сервиса для SPA

## Цель работы

Создание REST веб-сервиса в бэкенде системы для использования его в одностраничном приложении (SPA). Веб-сервис реализует всю бизнес-логику домена паттернов нагрузки без браузерного интерфейса, подключается к PostgreSQL через ORM, хранит загружаемые изображения и видео в MinIO.

## Общие требования

- Все URL веб-сервиса начинаются с префикса `/api/load_patterns` для домена паттернов и `/api/users` для домена пользователей.
- Все операции с базой данных выполняются через ORM SQLAlchemy.
- Удалённые записи (статус `deleted`) никогда не передаются клиенту — ни в списке, ни по прямому запросу через ID.
- Статусы паттерна образуют одностороннюю цепочку: `draft` → `published` при публикации, любой статус → `deleted` при удалении. Обратный переход запрещён.
- Системные поля — id, статус, creator_id, даты создания/публикации — не принимаются от клиента ни в одном методе, вычисляются сервером самостоятельно.
- Изображение и видео передаются как файлы через `multipart/form-data`, а не как текстовые ссылки. Загруженные файлы получают латинские имена при сохранении в MinIO.
- Текущий авторизованный пользователь определяется через сессию (см. раздел «Механизм определения текущего пользователя» ниже).

## Методы домена `load_patterns`

Всего реализовано **8 методов**.

| № | Метод | URL | Тело запроса | Тело ответа | Назначение |
|---|-------|-----|---------------|-------------|------------|
| 1 | GET | `/api/load_patterns` | Query: `max_expected`, `min_rps`, `max_rps`, `search`, `is_owner` | Список объектов + общее число найденных | Список опубликованных паттернов с фильтрацией |
| 2 | POST | `/api/load_patterns` | multipart/form-data: `pattern_name` (обязательно), `description`, `use_case`, `image`, `video` (необязательно) | Созданный черновик | Создать новый черновик паттерна нагрузки |
| 3 | GET | `/api/load_patterns/feed` | Query: `current_id`, `another` (0/1) | Один объект паттерна (не список) | Лента — одна случайная/следующая опубликованная запись |
| 4 | GET | `/api/load_patterns/draft` | Без параметров, без ID в URL | Черновик текущего пользователя | Получить незавершённый черновик текущего пользователя |
| 5 | GET | `/api/load_patterns/{pattern_id}` | Query: `next` (true/false) | Запрошенный или следующий объект | Получить паттерн по ID или следующий по кругу |
| 6 | PUT | `/api/load_patterns/{pattern_id}/publish` | JSON: `requests_per_second`, `peak_multiplier`, `duration_hours`, `description` и др. | Опубликованный объект | Публикация черновика: `draft` → `published` |
| 7 | DELETE | `/api/load_patterns/{pattern_id}` | — | Сообщение об успешном удалении | Логическое удаление собственного паттерна |
| 8 | POST | `/api/load_patterns/{pattern_id}/like` | JSON: `value` (0/1) | Сообщение об изменении лайка | Поставить/снять лайк |

Методы **1, 3, 4, 5** доступны без авторизации (гостю). Методы **2, 6, 7, 8** требуют авторизации через сессию, методы 6/7 доступны только автору записи.

## Методы домена `users`

Всего реализовано **3 метода**.

| № | Метод | URL | Тело запроса | Тело ответа | Назначение |
|---|-------|-----|---------------|-------------|------------|
| 1 | POST | `/api/users/register` | JSON: `username`, `email`, `password` | Данные пользователя без пароля | Регистрация, пароль хранится как хеш |
| 2 | POST | `/api/users/login` | JSON: `username`, `password` | Сообщение об успехе + `Set-Cookie: session_id` | Аутентификация, создание сессии в Redis |
| 3 | POST | `/api/users/logout` | — (cookie передаётся автоматически) | Сообщение о завершении сессии | Деавторизация, удаление сессии |

## Структура базы данных

### Таблица `users`

| Поле | Тип | Описание |
|------|-----|----------|
| id | integer, PK | Идентификатор пользователя |
| username | varchar, unique | Логин |
| email | varchar, unique | Электронная почта |
| password_hash | varchar | Хеш пароля |
| created_at | timestamp | Дата регистрации |

### Таблица `load_patterns`

| Поле | Тип | Описание |
|------|-----|----------|
| id | integer, PK | Идентификатор паттерна |
| pattern_name | varchar | Название паттерна нагрузки |
| pattern_code | varchar | Короткий код паттерна |
| status | enum (draft / published / deleted) | Статус записи |
| expected_request_count | bigint, nullable | Матожидание числа запросов |
| average_request_count | integer, nullable | Среднее число запросов |
| requests_per_second | integer, nullable | Запросов в секунду |
| peak_multiplier | numeric, nullable | Коэффициент пикового всплеска |
| duration_hours | integer, nullable | Длительность в часах |
| description | text, nullable | Описание |
| use_case | varchar, nullable | Сценарий применения |
| image_url | varchar, nullable | Ссылка на изображение в MinIO |
| video_url | varchar, nullable | Ссылка на видео в MinIO |
| base_cpu_cores | integer, nullable | Базовое число ядер CPU |
| base_ram_gb | integer, nullable | Базовый объём RAM |
| created_at | timestamp | Дата создания |
| updated_at | timestamp | Дата последнего обновления/публикации |
| creator_id | integer, FK → users.id | Идентификатор создателя |

### Таблица `pattern_likes`

| Поле | Тип | Описание |
|------|-----|----------|
| id | integer, PK | Идентификатор лайка |
| user_id | integer, FK → users.id | Пользователь, поставивший лайк |
| pattern_id | integer, FK → load_patterns.id | Паттерн |

На пару `(user_id, pattern_id)` наложено ограничение уникальности — один пользователь не может поставить больше одного лайка одному паттерну. Внешние ключи **без каскадного удаления**.

## Механизм определения текущего пользователя

> В исходной версии данной лабораторной работы текущий пользователь определялся функцией-одиночкой (singleton), возвращающей постоянный идентификатор без реальной проверки личности. В лабораторной работе №4 этот механизм полностью заменён на авторизацию через сессии в Redis, передаваемые клиенту через httponly cookie. Подробности — в разделе ЛР4.

## Технологический стек

- Backend: FastAPI (Python 3.10+)
- ORM: SQLAlchemy + Alembic (миграции)
- База данных: PostgreSQL
- Хранилище файлов: MinIO (S3-совместимое)
- Формат передачи медиафайлов: multipart/form-data
